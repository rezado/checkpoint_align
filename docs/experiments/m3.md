# M3 occurrence calibration

`run_calibration.py` is the thin orchestration boundary for existing catalog,
occurrence, alignment, and NEMU-position artifacts. It requires explicit
globally unique synchronization keys for large traces unless the complete
canonical `(semantic_key, occurrence, event_phase)` streams are identical.
A repeated anchor with only a local checkpoint occurrence is rejected as
`NO_SYNC_ANCHOR`; its local ordinal is never promoted to a QEMU-global
occurrence.

Example:

```sh
python3 scripts/m3/run_calibration.py \
  --source-trace data/results/qemu-occurrence/libquantum-reference/A/occurrences.json \
  --target-trace data/results/qemu-occurrence/libquantum-reference/B/occurrences.json \
  --source-window data/results/m3/runtime/libquantum-A28258-B28259/reference-A-from-scratch-window.json \
  --source-index 6594 \
  --output data/results/m3/runtime/libquantum-A28258-B28259/calibration-summary.json
```

The reference-input report is regenerated only after the projected B-native
checkpoint passes compression, post-checkpoint occurrence, functional-output,
and terminal-restore checks:

```sh
python3 scripts/m3/validate_reference_calibration.py \
  --candidate-root data/results/m3/runtime/libquantum-A28258-B28259 \
  --source-qemu-dir data/results/qemu-occurrence/libquantum-reference/A-repeat \
  --target-qemu-dir data/results/qemu-occurrence/libquantum-reference/B-current \
  --repeat-qemu-dir data/results/qemu-occurrence/libquantum-reference/A-repeat \
  --source-firmware data/multi-workload/workloads/libquantum/A/bin/libquantum.fw_payload.bin \
  --target-firmware data/multi-workload/workloads/libquantum/B/bin/libquantum.fw_payload.bin \
  --nemu local-src/NEMU/build/riscv64-nemu-interpreter \
  --restorer data/multi-workload/tools/gcpt.bin \
  --output data/results/m3/runtime/libquantum-A28258-B28259/validation-summary.json
```

## Debug-preserving validation build

`build_debug_preserving.py` derives a temporary SPEC config from the frozen
reference config, replaces `-flto` with `-fno-lto`, adds `-g`, and builds
`462.libquantum` without changing the reference source tree or reference ELF:

```sh
python3 scripts/m3/build_debug_preserving.py \
  --spec /path/to/spec-src \
  --config /path/to/riscv_gcc16_base.cfg \
  --compiler-root /path/to/riscv-gcc16 \
  --jemalloc-root /path/to/jemalloc/install \
  --out-dir data/results/m3/runtime/libquantum-debug-preserving
```

The resulting `build-manifest.json` and DWARF catalog are build-bound. The
reference-input full run is intentionally a separate, potentially long,
calibration step; an interrupted or partial QEMU trace is never accepted as a
calibration result.

For the measured libquantum case, `-g -flto` still leaves
`quantum_sigma_x` symbol-only, while disabling LTO for every object makes the
QEMU reference input unnecessarily slow. `--hybrid-gates` is the measured
minimal variant: only `gates.c` is compiled with `-g -fno-lto`; the other
objects retain LTO. `--march` derives the target build with its real ISA flags.

The accepted M-level calibration report is regenerated from QEMU traces, NEMU
hits, compressed checkpoints, and terminal restore logs:

```sh
python3 scripts/m3/validate_debug_calibration.py \
  --source-root data/results/m3/runtime/libquantum-debug-hybrid-A \
  --target-root data/results/m3/runtime/libquantum-debug-hybrid-rva23-B \
  --nemu local-src/NEMU/build/riscv64-nemu-interpreter \
  --restorer data/multi-workload/tools/gcpt.bin \
  --output data/results/m3/runtime/debug-preserving-m-calibration.json
```

This report applies only to the separate debug-preserving validation builds;
it does not upgrade the symbol-only reference `A28258->B28259` result above L.
